# 开发与构建

## 对应源码

`native-source/` 是当前修改后的完整源码快照，基于水杉 `v0.11.1`，基准提交为 `dd018f79858314ed542a47c528608752b13bd261`。两个 vendor 子模块已按固定提交展开，下载源码包即可读取它们，无需依赖开发机器的临时目录。

`docs/PROVENANCE.json` 记录本体哈希、上游和 vendor 提交；`patches/kasumi-native-v053.patch` 是相对基准的完整差异。源码与对应二进制可在同一 GitHub Release 获取。

## 编译原生本体

需要 Windows x64、Visual Studio C++ Build Tools、Windows SDK、CMake、Ninja、vcpkg，以及 `x64-windows-static-md` 的 Boost。当前已验证构建使用 MSVC 14.51、Windows SDK 10.0.26100.0、CMake 4.4 和 Ninja 1.13；C++ 格式化版本为 clang-format 18.1.8。

在 x64 Native Tools / Developer PowerShell 中设置自己的依赖路径，再运行：

```powershell
$env:VCPKG_ROOT = 'D:\tools\vcpkg'
$env:BOOST_ROOT = 'D:\tools\vcpkg\installed\x64-windows-static-md'
.\tools\Build-Native.ps1
```

本脚本使用 Ninja Multi-Config，并保留上游 CMake 的依赖定义。编译器必须能在当前终端找到；更改工具链或公共结构体后，不要复用其他生成器遗留的 obj/PDB。建议使用短的纯 ASCII 源码与构建路径，避免部分依赖工具的 Unicode 路径问题。

产物位于 `build/native/bin/Release/MetasequoiaImeServer.exe`。构建不会安装或重启输入法。自编二进制的哈希未必与发布文件相同；发布安装器只接受清单声明的文件，不应直接跳过哈希检查。

## 显示逻辑

- `CandidateWidthLimitedCard` 在同一绘制目标上依次画固定比例背景、右锚前景、候选文字和品丝。
- 背景可见区域随实际卡宽裁切，前景按右端移动。源图比例不随长度改变。
- 品丝读取当前已排列的候选矩形，不均分总宽，也不依赖日志轮询。
- `single_line` 只影响显示布局和省略，不修改实际候选内容与选择索引。
- 显隐由原生候选窗自己的 Present/Cloak 流程处理，运行时无需 C# 浮层。

## 重新导出分层素材

原图与遮罩位于 `skin/kasumi-adaptive/assets/`。`tools/Export-NativeBandLayers.ps1` 使用历史 Diagnostics 程序中的实际分层算法，输出两张 `native-band-*.png` 及本地验证报告，不启动驻留进程。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Export-NativeBandLayers.ps1
```

原图、遮罩或比例参数变化后，应同时重导出图层、审核效果并更新发布清单。原有两层的源分辨率为 2172×724，显示基准为 1032×344 DIP。

## 发布边界

`packaging/` 是运行包目录的模板。Git 中不保存生产 Server EXE；发布时放入匹配的 `packaging/native/MetasequoiaImeServer.exe`，更新并核对 `release-manifest.json`，再打包此目录。普通用户使用 Release 的 Windows ZIP。

代码沿用各目录原有许可，native-source 包含上游及 vendor 许可。不要将本机输入日志、用户词库、配置、备份或凭据加入发布内容。
